# 题库、审核与评测接口文档

版本：`v1`  
机器可读契约：`openapi-question-bank.yaml`

## 1. 服务和权限边界

| 调用方 | 数据库角色 | 可访问内容 |
|---|---|---|
| 学生题目服务 | `app_student_api` | `student_quiz_bank_safe`，不含答案 |
| 可信评分服务 | `app_scoring_service` | `internal_quiz_scoring_bank`、提交与评分表 |
| 内容审核服务 | `app_content_reviewer` | 审核队列、候选映射和发布批次 |
| 内容发布服务 | `app_content_publisher` | 只能调用受控发布函数，不能直接更新题库状态 |

前端不能直连数据库。HTTP 服务从 Bearer Token 中取得用户或审核人身份。学生请求事务必须执行 `SET LOCAL app.current_user_id='<服务端验证的用户 ID>'`，数据库 RLS 会再次限制 assignment、提交、结果和幂等记录的用户范围。

## 2. 通用规则

请求头：

```text
Authorization: Bearer <token>
Content-Type: application/json
Idempotency-Key: <uuid>   # 所有写接口必填
```

统一错误：

```json
{
  "error": {
    "code": "CONTENT_NOT_READY",
    "message": "The requested question is not published.",
    "requestId": "req-...",
    "details": {}
  }
}
```

建议状态码：`400` 参数错误、`401` 未登录、`403` 无权限、`404` 不存在、`409` 状态或幂等冲突、`422` 未满足发布条件、`500` 内部错误。

## 3. 创建下一道 Quiz assignment

```text
POST /v1/assessment/assignments/next
```

请求：

```json
{
  "knowledgePointId": "kp-...",
  "diagnosticId": "diagnostic-...",
  "mode": "diagnostic",
  "locale": "zh-CN",
  "excludeSeenWithinDays": 7
}
```

这是写接口，必须提供 `Idempotency-Key`。服务端只能从安全视图选题，并在同一事务写入 `assessment_assignments`。请求 `zh-CN` 时优先读取 `student_quiz_localized_bank_safe`；若中文未发布则回退到英文。assignment 固化题目版本、知识点、评测规格、选题算法和过期时间，防止提交时替换题目。

响应：

```json
{
  "assignmentId": "assignment-...",
  "questionId": "item-...",
  "versionId": "item-version-...",
  "locale": "zh-CN",
  "fallbackUsed": false,
  "title": "Pre-Quiz",
  "stem": "Question text",
  "options": [
    {"key": "0", "text": "Option A", "sortOrder": 0},
    {"key": "1", "text": "Option B", "sortOrder": 1}
  ],
  "knowledgePointIds": ["kp-ml-intro"],
  "source": {
    "sourceId": "microsoft-ml-for-beginners",
    "url": "https://github.com/..."
  },
  "selection": {
    "algorithm": "diagnostic-selector",
    "version": "1.0.0",
    "reasonCodes": ["TARGET_KNOWLEDGE_POINT"]
  },
  "expiresAt": "2026-08-12T12:00:00Z"
}
```

该响应禁止出现答案、正确项、解释中的答案提示或内部评测配置。`locale` 表示实际返回语言，`fallbackUsed=true` 表示请求语言尚未发布而回退英文。

## 4. 提交 Quiz 答案

```text
POST /v1/assessment/submissions
```

请求：

```json
{
  "assignmentId": "assignment-...",
  "versionId": "item-version-...",
  "selectedOptionKey": "1",
  "responseTimeMs": 8400,
  "hintCount": 0
}
```

事务内执行：

1. 锁定 assignment，确认属于当前用户、未过期且状态为 `offered`；
2. 验证请求中的 `versionId` 与 assignment 完全一致；
3. 从登录上下文取得 `user_id`；
4. 在 `api_idempotency_records` 按 `actor_id + endpoint + key` 占位并校验请求哈希；
5. 写入 `task_submissions.assessment_assignment_id`；
6. 将 `selectedOptionKey` 与 `internal_quiz_scoring_bank.correct_option_key` 比较；
7. 写入 `evaluation_results` 和唯一的 `assessment_evidence`；
8. 将 assignment 标记为 `submitted` 并提交事务。

响应：

```json
{
  "submissionId": "submission-...",
  "status": "completed",
  "result": {
    "score": 1.0,
    "isPassed": true,
    "confidence": 1.0,
    "reasonCodes": ["EXACT_ANSWER_MATCH"],
    "evaluatorName": "exact-answer",
    "evaluatorVersion": "1.0.0"
  },
  "explanation": {
    "locale": "zh-CN",
    "fallbackUsed": false,
    "summary": "本题考查……",
    "correctReason": "……",
    "optionReasons": {"A": "……", "B": "……"},
    "memoryTip": "……",
    "sourceUrls": ["https://github.com/..."]
  }
}
```

`explanation` 只能在评分状态为 `completed`、解析已经审核发布并且提交属于当前用户时返回。数据库访问使用 `get_student_quiz_feedback(submissionId, locale)`；做题前接口绝对不能查询或缓存解析。

相同幂等键和相同请求哈希返回 `api_idempotency_records` 保存的原结果；相同键但请求哈希不同返回 `409 IDEMPOTENCY_CONFLICT`。一个 assignment 只能产生一条提交。

## 5. 查询评分结果

```text
GET /v1/assessment/submissions/{submissionId}/result
```

只允许提交所属用户或具备管理权限的账号访问。结果可包含分数和反馈，但不返回内部答案对象。

## 6. 获取审核队列

```text
GET /v1/admin/content/review-queue?status=BLOCKED_REVIEW&sourceId=...
```

数据来自 `publication_readiness`。管理端可看到题干、参考答案、来源、候选映射、审核状态和阻塞原因。

响应中的 `readinessStatus` 为：

```text
BLOCKED_SOURCE
BLOCKED_ANSWER
BLOCKED_CORRECT_OPTION_COUNT
BLOCKED_TARGET_MAPPING
BLOCKED_REVIEW
BLOCKED_EXACT_EVALUATION
READY
```

`blockerCodes` 返回全部阻塞原因；`readinessStatus` 只是其中第一项，完全无阻塞时才为 `READY`。

## 7. 审核知识点候选映射

```text
POST /v1/admin/content/mappings/{candidateId}/decision
```

请求：

```json
{
  "decision": "approved",
  "reviewNote": "Matches the upstream lesson topic."
}
```

允许 `approved` 或 `rejected`。审核人来自登录上下文，服务端写入 `reviewed_by` 和 `reviewed_at`。批准候选不等于发布题目；正式发布批次才创建 `item_knowledge_maps`。

## 8. 审核题目答案和来源

```text
POST /v1/admin/content/items/{versionId}/review
```

请求：

```json
{
  "reviewStatus": "approved",
  "checkedAnswer": true,
  "checkedMapping": true,
  "checkedSource": true,
  "reviewNote": "Answer and source verified against pinned commit."
}
```

只有三项均为 `true` 的 `approved` 记录满足发布条件。修改题干或答案时必须创建新版本，不原地覆盖已经产生作答记录的版本。

## 9. 验证并发布批次

```text
POST /v1/admin/content/publication-batches/{batchId}/publish
```

请求：

```json
{
  "batchName": "Quiz release 2026-01",
  "versionIds": ["item-version-..."],
  "expectedSourceCommits": {
    "microsoft-ml-for-beginners": "d0d0ea2b...",
    "microsoft-ai-for-beginners": "33e781bf..."
  }
}
```

服务端根据已审核内容计算不可变 manifest，并调用 `publish_quiz_batch(...)`。函数在同一事务中验证、建立审核批次、发布并记录结果，不允许应用直接更新题库状态。

要求：

- 调用者有发布权限；
- 批次 ID 和 manifest 从未使用；
- 来源 Commit、内容哈希、题干、答案文本和正确选项都与审核快照一致；
- 每题具有待批准/已批准的目标映射候选和唯一正确项；
- 只能由 `app_content_publisher` 调用 `publish_quiz_batch(...)`；
- 发布使用单个数据库事务。

成功后题目、评测规格和任务模板为 `published`，正式映射已写入，发布批次保存操作者和时间。

## 10. 审核并发布中文翻译和解析

审核接口：

```text
POST /v1/admin/content/localizations/{versionId}/review
```

请求：

```json
{
  "locale": "zh-CN",
  "translationReviewStatus": "approved",
  "explanationReviewStatus": "approved",
  "checkedStem": true,
  "checkedOptions": true,
  "checkedExplanation": true,
  "reviewNote": "术语、选项等价性和解析已核对。"
}
```

翻译审核和解析审核相互独立。审核人必须确认：

- 中文题干没有改变原题条件、否定词或范围；
- 每个中文选项与英文选项一一对应，正确项 key 不变；
- CNN、RNN、KNN、ARIMA、Transformer 等术语符合统一词汇表；
- 解析说明了正确理由，错误选项的差异不是通用占位语；
- 解析来源链接仍指向固定 Commit 的原课程。

发布接口：

```text
POST /v1/admin/content/localization-publication-batches/{batchId}/publish
```

基础英文题必须先发布。翻译和解析均为 `approved`、审核人非空且 manifest 未使用时，才能在一个事务内发布中文题干、选项和解析。机器生成的 `pending` 内容不能直接发布。

## 11. 算法接入契约

选题器输入建议：

```json
{
  "userId": "server-context",
  "mode": "diagnostic",
  "targetKnowledgePointIds": ["kp-..."],
  "candidateVersionIds": ["item-version-..."],
  "masterySnapshot": {},
  "constraints": {"limit": 1, "excludeSeenWithinDays": 7}
}
```

选题器输出：

```json
{
  "selectedVersionIds": ["item-version-..."],
  "algorithm": "diagnostic-selector",
  "algorithmVersion": "1.0.0",
  "reasonCodes": ["LOW_MASTERY", "COVERAGE_GAP"],
  "decisionSnapshot": {}
}
```

评分器输入和输出必须以题目版本和评测规格版本为主键。替换 IRT/BKT、规则评分器或 LLM 评分器时，写入新版本结果，不覆盖历史记录。

掌握度算法的正式接口、五个安全视图、五级掌握状态、四级记忆状态、证据防重和版本冲突规则见 `03-算法接入与掌握度协议.md`。算法只能调用 `apply_mastery_update(...)`，不能直接更新 `learner_mastery_current`。

## 12. 接口测试最低要求

- 学生题目响应递归扫描后不存在 `answerData`、`answer_data`、`isCorrect`、`is_correct`；
- 未发布、无正式映射或无已发布规格的题目返回 `404/422`，不能被选题；
- 学生 A 无法读取学生 B 的提交；
- 重复幂等请求不会产生两条提交或两份证据；
- 无审核权限者无法调用管理接口；
- 有阻塞项的发布批次无法发布；
- 发布事务失败时所有状态回滚；
- 重复批次 ID、重复 manifest、Commit 或题目内容变化时发布失败；
- assignment 不能被其他用户提交，不能提交不同 `versionId`；
- `selectedOptionKey` 必须与服务端 `correct_option_key` 比较，不能与答案文本比较。
- 请求 `zh-CN` 但中文未发布时必须回退英文并标记 `fallbackUsed=true`；
- 中文选项顺序和 key 必须与英文版本一致；
- 作答前响应不含 `explanation`；未完成、他人或不存在的提交不能取得解析；
- 机器生成但未审核的中文内容不得出现在学生安全视图。
- 算法角色不能读取答案字段、提交 payload 或隐藏测试；
- 同一证据不能更新两次掌握度，同一 `updateId` 重放必须返回原状态版本；
- 过期的 `expectedStateVersion` 必须返回冲突；
- 循环前置关系的发布批次必须整体回滚。
