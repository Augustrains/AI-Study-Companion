# 自适应伴学接口总契约

本文说明算法与业务模块的边界。题库、审核和发布接口的字段级定义见：

- `02-题库审核与评测接口.md`
- `03-算法接入与掌握度协议.md`
- `openapi-question-bank.yaml`

## 接口与算法

| 接口 | 主要能力 | 主要输出 |
|---|---|---|
| `GET /v1/books/{bookId}/learning-map` | A01 知识图谱 | 能力、知识点、前置关系 |
| `POST /v1/diagnostics` | A01 + A02 诊断选题 | 已发布题单、覆盖理由 |
| `POST /v1/diagnostics/{id}/finish` | A03 + A05 评测与状态更新 | 判断、证据、状态变化 |
| `POST /v1/learner-calibrations` | A04 + A05 用户校准 | 校准记录、计划建议 |
| `POST /v1/learning-plans` | A04 任务排序 | 新学、练习、复习、复测任务 |
| `POST /v1/learning-events` | A05 学习闭环 | 事件及待重算对象 |
| `POST /v1/assessment/assignments/next` | Quiz 选题与 assignment 固化 | assignment ID、不含答案的题目 DTO |
| `POST /v1/assessment/submissions` | A03 确定性评分 | 得分、原因码、评测版本 |
| `POST /v1/practice/submissions/{id}/evaluate` | 可替换实践评分器 | 测试/Rubric 结果和证据强度 |
| `POST /v1/rag/answers` | A06 RAG | 回答、引用、关联知识点 |
| `GET /v1/learners/me/knowledge-status` | A05 当前状态 | 五级掌握度、记忆状态、下次复习 |
| `GET /v1/learners/me/mastery-history` | A05 状态追溯 | 版本、原因码和历史变化 |
| `GET /v1/internal/mastery/evidence-events` | 算法内部证据流 | 不含答案的可用证据 |
| `POST /v1/internal/mastery/updates` | A05 受控状态更新 | 幂等写入结果和新状态版本 |

## 共同约束

- API 路径以 `/v1` 开头；
- JSON 字段使用 `camelCase`，数据库字段使用 `snake_case`；
- `userId` 从鉴权上下文取得，不接受客户端冒充；
- 所有写接口支持 `Idempotency-Key`；
- 幂等键及请求哈希保存到 `api_idempotency_records`；
- 时间使用 ISO 8601 UTC；
- 所有算法输出保存算法名称、版本、原因码和输入证据；
- 算法不得直接修改题目、答案、正式映射、旧评分或掌握度基表；
- 掌握度更新必须携带证据 ID、算法版本和 `expectedStateVersion`，并调用受控数据库函数；
- 学生接口不得返回 `answer_data`、`is_correct`、隐藏测试或内部评测配置。

## 核心流程

```text
已审核 Quiz + 正式知识点映射
→ 选题算法
→ assessment_assignments + 学生安全题目 DTO
→ 用户提交
→ 服务端 exact-answer 评分
→ evaluation_results
→ assessment_evidence
→ 掌握度算法
→ apply_mastery_update（证据去重 + 乐观锁 + 历史）
→ 学习计划
```

## RAG 边界

`POST /v1/rag/answers` 可以返回回答、来源引用、关联知识点和建议动作，但不能直接改变用户掌握状态。只有可追溯评测证据才能触发掌握度更新。
