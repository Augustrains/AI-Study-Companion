# 题库运营与人工确认导览

本文件把 PRD 要求的“诊断 → 学习练习 → 复测 → 状态更新”落实为可交接文件。系统已自动生成结构、选题规则和待办；**学科内容正确性仍必须由人工确认**。

## 已自动完成

| 文件 | 当前作用 | 系统如何使用 |
|---|---|---|
| `data/question_delivery_profile.csv` | 150 道题的诊断/练习/复测用途、曝光上限、建议用时和认知层级 | 诊断优先选 `diagnostic`；练习按用时、难度和曝光次数轮换；复测优先避开已做题。 |
| `data/question_pool_expansion_backlog.csv` | 37 个知识点由当前 4 题扩至建议 7 题的内容待办 | 当前题池不足以做到诊断与复测完全不重复时，服务明确返回 `limited_reuse`，不会假装题池充足。 |
| `data/question_wrong_option_review.csv` | 450 条选项审核行 | 已记录用户实际选择；审核人确认错因标签后，长期记录才能显示具体误解和补救知识点。 |
| `data/mastery_task_auto_grading_spec.csv` | 37 道应用任务的结构化字段、答案键和确定性分值规则 | 服务只下发字段和选项；提交后立即自动评分并写入证据，答案键不下发前端。 |
| `data/mastery_task_scoring_card.csv` | 历史评分卡工作表 | 仅供内容设计和抽检，不进入学习者实时评分链路。 |

## 必须由内容负责人确认

系统已在 `question_ai_pre_review.csv`、`mastery_task_ai_pre_review.csv` 和 `wrong_option_ai_pre_review.csv` 填入 AI 初审建议。审核人可以参考，但必须自行对照教材和题目作出 `approved / rewrite / reject` 结论；AI 建议不能直接复制为正式审核结果。

1. 在 `question_pre_review.csv` 审核 37 道基础题：题干、正确答案、干扰项、难度和教材出处；填写 `human_decision`、审核人和日期。
2. 在 `question_wrong_option_review.csv` 为每个错误选项填写真实的 `misconception_label`、补救知识点，并将可用行的 `status` 改为 `active`。不要把“未确认”错因直接用于计划调整。
3. 在 `mastery_task_auto_grading_spec.csv` 核对每题的字段、答案键、容差和分值；确认后将 `content_review_status` 标为 `human_confirmed`。它不需要在学习者提交后人工打分，题库质量门控仍须独立确认。
4. 按 `question_pool_expansion_backlog.csv` 为每个知识点补 3 道不同情境的题，优先补独立复测与真实应用、调试、实现或建模题；不得用换序题凑数量。

## 状态升级边界

`target_level=掌握` 只表示题目属于掌握证据链。系统只有同时收到：多题型证据、无提示复测、高分应用证据、自动判分应用任务，并且 `question_quality_gate.csv=eligible` 时，才可将 AI 状态升级为“掌握”。

## 每次内容更新后的检查

```text
npm run build:question-operations
npm run build:hierarchy-tags
npm run audit:question-quality
npm test
```

严格发布检查 `npm run verify:release` 会在仍有人工审核待办时失败；这是正常的安全拦截，不应绕过。

真实试用后的题库校正指标见 `../../06-质量验证/题库试用与校正指标.md`。
