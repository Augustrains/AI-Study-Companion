# 非选择题自动判分规则

> 适用范围：37 个“掌握任务”及后续新增的非选择题。  
> 核心要求：学习者提交后必须实时得到可复现的判定结果；人工只在题目制作阶段定义标准答案、测试样例和判分边界，**不参与实时评分**。

## 一、先改变题目形态，才能做到客观判分

不是所有“开放表达”都能客观自动判分。用于状态升级的非选择题必须改写为机器可验证的结构化任务；纯主观讨论可保留为学习反馈，但不能作为“掌握”证据。

| 原始题型 | 可自动判分的改写方式 | 自动判定依据 | 是否可进入“掌握”证据链 |
|---|---|---|---|
| 简答/概念解释 | 填空、术语匹配、关键步骤排序、结构化字段填写 | 精确答案键或允许答案集合 | 可以 |
| 计算/推导 | 公式填空 + 关键中间值 + 最终数值 | 等价公式、数值容差、步骤答案键 | 可以 |
| 代码阅读/调试 | 提交补丁或函数输出，不提交自由说明 | 公开/隐藏测试、静态规则、预期报错修复 | 可以 |
| 编程实现 | 固定函数签名、输入输出约束、资源限制 | 隔离执行环境中的公开/隐藏单元测试 | 可以 |
| 案例建模 | 固定字段：任务类型、指标、模型类别、理由标签 | 结构化答案键、约束校验、可接受组合表 | 可以，前提是已结构化 |
| 自由论述/项目报告 | 仅用于学习反馈或作品展示 | 无统一客观答案 | 不可以 |

## 二、人工在什么时候参与

人工工作前置到**题目发布前**，不出现在学习者的实时流程中：

1. 内容负责人把每道应用任务改写成可自动判分的提交格式。
2. 为任务填写答案键、允许答案、数值容差、公开测试、隐藏测试或结构化字段规则。
3. 用已知正确、部分正确、典型错误答案验证规则，确认分数与预期一致。
4. 将自动判分规范设为 `approved` 后，题目才可用于“掌握”证据链。

运行时的流程是：

```text
学习者提交结构化答案 / 代码
        ↓
规则引擎或隔离代码执行器自动评分
        ↓
立即返回：得分、通过项、未通过项、可复现的测试结果
        ↓
写入学习证据并重新计算知识状态
        ↓
仍须同时满足：多题型、无提示复测、足够平均分、质量门控
        ↓
才可能升级为“掌握”
```

AI 可以解释错误或推荐下一步，但不得充当裁判；它的回答不影响客观分数。

## 三、每道自动判分任务需要的数据

正式表为：`mastery_task_auto_grading_spec.csv`。当前 37 道应用任务均已有一行规格；一行至少包括：

| 字段 | 含义 |
|---|---|
| `mastery_task_id` | 对应任务 ID |
| `grading_type` | `exact_match`、`numeric_tolerance`、`ordered_steps`、`structured_fields` 或 `code_tests` |
| `response_schema_json` | 学习者提交格式，例如数值、步骤数组、字段对象或指定函数 |
| `answer_key_json` | 正确答案、可接受答案集合或结构化答案键 |
| `tolerance` | 数值允许误差；非数值题为空 |
| `public_test_spec_json` | 可展示给学习者的测试样例 |
| `hidden_test_reference` | 服务端保管的隐藏测试标识；不能下发前端 |
| `scoring_rules_json` | 各项得分和总分的确定性计算规则 |
| `status` | 只有 `approved` 才能参与状态升级 |

代码题还必须有隔离运行环境、超时限制、内存限制和禁止网络访问；不能在主服务进程直接执行用户代码。

## 四、示例：折扣回报推导题

原题“写出并计算折扣回报”不够客观，因为过程表述可以有很多写法。改写后：

```text
输入字段：
gamma = 0.5
step_1_term = 2
step_2_term = 1.5
step_3_term = 1.25
return_value = 4.75
terminal_value = 0
```

系统规则：逐字段与答案键比对；数值按 `tolerance=0.0001` 判断。可定义“所有字段正确得 4 分；最后结果正确但缺少一个关键中间项得 3 分”。全过程无需人工当场判断。

## 五、对当前 37 道任务的影响

37 道任务已经全部转换为 `structured_fields`：服务端可实时核验数字、术语选择、集合、步骤顺序和固定公式字段。质量验证会逐题以正确答案测试满分、以错误字段测试扣分；人工评分接口已停用。

仍由内容负责人离线完成的工作是：

1. 对照教材逐题核对答案键与可接受选项；
2. 将 `content_review_status` 从 `ai_pre_assessed_pending_human` 改为 `human_confirmed`；
3. 对需要真实代码执行的新题，新增隔离测试运行器后再使用 `code_tests`，不能在主服务进程执行用户代码；
4. 在 `question_quality_gate.csv` 完成题库质量确认前，继续阻止“掌握”自动升级。

这些离线核对不进入学习者的实时路径：学习者提交后始终立即得到确定性结果与更新后的学习建议。
