# 前端交互与后端交接说明

## 文档状态

- 版本：v0.2
- 读者：后端、算法、产品和前端开发人员
- 目的：统一页面行为、状态名称、接口边界和数据要求
- 当前阶段：前端完整演示与接口联调准备阶段

## 0. 当前前端演示范围

当前只展示两本学习内容：

- 《机器学习》：监督学习、模型评估、偏差与方差、正则化。
- 《强化学习》：马尔可夫决策过程、价值函数、Q 学习、探索与利用。

切换学习内容后，今日学习、能力图谱、诊断题、学习计划、学习记录和资料问答会同步切换。前端默认使用模拟服务，模拟服务与真实接口使用相同的动作名称和数据方向。

## 1. 当前依据与边界

当前提供的 `自适应伴学智能体-Flowchart.md` 文件只有标题，没有具体流程节点。本说明暂以以下文档为业务依据：

- `interfaces/01-接口契约.md`
- `docs/01-系统边界与职责.md`
- `docs/02-开发顺序与分工.md`

### 前端负责

- 页面展示。
- 用户输入和确认。
- 页面之间的导航。
- 触发后端动作。
- 展示后端返回的判断、依据、计划和事件结果。
- 处理加载、空数据、失败、重试和恢复状态。

### 前端不负责

- 掌握度计算。
- 诊断题选择规则。
- 学习计划排序算法。
- RAG 检索和回答生成。
- 数据库写入规则。
- 用聊天内容自动修改用户状态。

## 2. 页面与交互路径

| 页面 | 建议路径 | 核心目的 | 主要操作 |
|---|---|---|---|
| 今日学习 | `/today` | 告诉用户下一步做什么 | 开始推荐任务、查看计划、查看待复测 |
| 选书与目标 | `/goals/new` | 建立学习上下文 | 选择书籍、主题、目标水平、每周时间 |
| 能力诊断 | `/diagnostics/:diagnosticId` | 收集诊断证据 | 作答、查看提示、跳过、提交下一题 |
| 诊断结果 | `/diagnostics/:diagnosticId/result` | 展示 AI 判断和证据 | 查看依据、提交用户校准 |
| 学习计划 | `/plans/:planId` | 展示任务顺序和原因 | 开始任务、完成任务、调整目标 |
| 学习记录 | `/records` | 查看事件和复测安排 | 查看历史、进入复测、查看状态变化 |
| 资料问答 | `/qa` | 在学习上下文中提问 | 提问、追问、查看引用、加入计划 |

## 3. 页面状态清单

### 3.1 通用状态

所有页面至少需要支持：

- `initial`：尚未发起请求。
- `loading`：正在获取数据。
- `ready`：数据已准备好。
- `empty`：请求成功但没有数据。
- `submitting`：用户操作正在提交。
- `success`：操作成功。
- `error`：操作失败。
- `offline`：网络不可用。
- `stale`：页面数据可能已过期，需要刷新。

### 3.2 诊断会话状态

```text
not_started
  → in_progress
  → paused
  → submitted
  → evaluated
  → calibrated
```

前端只显示状态，不负责改变诊断状态的业务规则。

### 3.3 学习任务状态

```text
locked       未解锁
todo         未开始
in_progress  进行中
completed    已完成
review_due   待复测
skipped      已跳过
rescheduled  已重新安排
```

后端返回的状态名称需要保持稳定，前端只做展示映射。

## 4. 接口动作映射

| 用户动作 | 前端触发 | 后端负责 | 前端展示 |
|---|---|---|---|
| 选择书籍与目标 | 创建学习目标 | 保存目标并返回可诊断范围 | 当前书籍、主题、目标和可诊断能力 |
| 开始诊断 | 发起诊断 | 生成题单并返回覆盖理由 | 题目、进度、关联能力 |
| 提交答案 | 保存答案 | 保存作答记录并返回提交结果 | 选择结果、提交状态 |
| 完成诊断 | 完成诊断 | 生成 AI 判断、证据和复测建议 | 评估结果、依据、建议 |
| 提交用户校准 | 保存校准 | 新增校准记录并返回计划建议 | 校准成功、建议变化 |
| 生成学习计划 | 请求生成计划 | 按目标、状态和时间排序任务 | 任务列表、排序理由 |
| 完成学习任务 | 写入学习事件 | 保存事件并返回后续建议 | 完成状态、下一步推荐 |
| 发起资料问答 | 提交问题 | 检索资料并生成引用回答 | 回答、引用、关联知识点 |

## 5. 现有接口契约对应关系

### `GET /books/{bookId}/learning-map`

前端需要展示：

- 书籍信息。
- 章节。
- 能力。
- 知识点。
- 前置关系。
- 资料出处。

### `POST /learner-goals`

前端提交：

- `userId`。
- `bookId`。
- `topicId`。
- `targetLevel`。
- `weeklyHours`。

后端返回：

- `goalId`。
- 可诊断能力范围。
- 当前目标摘要。

### `POST /diagnostics/start`

后端需要返回：

- `diagnosticId`。
- 题目列表或首题。
- 总题数。
- 题目顺序。
- 每道题关联的能力或知识点。
- 题目覆盖理由。

### `POST /diagnostics/{diagnosticId}/answers`

建议保存：

- `questionId`。
- `answer`。
- `startedAt`。
- `submittedAt`。
- `clientRequestId`。

### `POST /diagnostics/{diagnosticId}/finish`

后端需要返回：

- AI 能力判断。
- 判断置信度。
- 正确题目和错误题目。
- 关联知识点。
- 判断依据。
- 建议复测项。

### `POST /learner-calibrations`

用户校准至少需要：

- `userId`。
- `knowledgePointId`。
- `userLevel`。
- `reason`。
- `createdAt`。

要求：用户校准作为新记录保存，不覆盖原始 AI 判断。

### `POST /learning-plans/generate`

后端返回的每项任务建议包含：

- `taskId`。
- `taskType`。
- `status`。
- `title`。
- `knowledgePointIds`。
- `estimatedMinutes`。
- `reasonCode`。
- `reasonText`。
- `dueAt`。
- `reviewAt`。

### `POST /learning-events`

事件类型建议包括：

- `task_started`。
- `task_completed`。
- `question_answered`。
- `diagnostic_finished`。
- `calibration_submitted`。
- `review_completed`。
- `question_asked`。

### `POST /rag/ask`

后端返回：

- 回答内容。
- 引用列表。
- 引用标题。
- 来源文件或章节。
- 页码或定位信息。
- 关联知识点。
- 薄弱项提醒。
- 推荐动作。

要求：RAG 问答不能直接修改用户掌握状态。

## 5.1 前端当前已演示的交互

前端已经提供以下可点击页面演示，后端只需要接收动作并返回数据：

- 诊断逐题保存、上一题、跳过、暂停、继续、提交和失败提示。
- 诊断结果依据展开、用户校准和校准原因保存。
- 学习任务详情、开始、完成和进度变化。
- 学习目标调整、计划总览与知识点列表切换。
- 学习记录分类筛选、记录详情和复测入口。
- 资料问答等待、失败重试、引用展开、来源预览和加入计划。
- 设置与帮助模块的弹窗入口。

这些交互目前由模拟服务驱动。真实接口接入后，页面保留相同的加载、成功、空数据、错误和重试反馈。

## 6. 前后端交接要求

### 必须稳定的字段

- 所有实体都需要稳定唯一 ID。
- 所有状态字段使用固定枚举。
- 所有时间字段统一使用带时区的时间格式。
- 所有推荐任务都提供 `reasonCode` 和可读的 `reasonText`。
- 所有 AI 判断都提供可追溯依据。
- 所有写入动作支持 `clientRequestId`，避免重复提交。

### 建议统一的错误结构

后端错误至少需要包含：

- `code`：稳定错误码。
- `message`：用户可读信息。
- `requestId`：请求追踪 ID。
- `retryable`：是否允许前端重试。
- `details`：开发调试信息，可选。

### 前端对错误的处理

- `retryable = true`：展示“重新尝试”。
- `retryable = false`：展示原因和下一步建议。
- 诊断提交失败：保留用户答案，允许重新提交。
- 计划生成失败：保留诊断和校准结果，不清空页面。
- 问答失败：保留用户输入，允许重新发送。

## 7. Mock 数据与真实接口替换原则

前端开发阶段使用 Mock 数据，但 Mock 字段必须与接口契约保持一致。

后端接入时只替换：

- 数据请求层。
- 数据转换层。
- 错误处理适配层。

页面组件不应直接依赖数据库字段，也不应在组件内编写掌握度、选题或计划排序规则。

### 前端切换真实接口

开发阶段默认使用模拟服务。后端准备好后，在前端环境变量中配置：

```text
VITE_USE_REAL_API=true
VITE_API_BASE_URL=http://后端地址
```

页面不直接修改请求地址。`src/services/api.ts` 会根据配置选择模拟服务或真实服务；若后端字段命名不同，只在该文件增加转换。

## 9. 待确认问题

以下问题需要产品、算法和后端共同确认：

1. 诊断过程中是否允许返回上一题。
2. 用户暂停诊断后，题目答案保存多久。
3. “用户校准”采用三级选项还是连续等级。
4. 学习任务完成的判定由哪个接口返回。
5. 复测任务是否自动加入下一轮计划。
6. 资料问答是否允许用户切换书籍或章节范围。
7. 资料引用需要精确到页码、段落还是文档章节。
